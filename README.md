# LINK CORE（My Desktop）

自分のリンクを、macOS の Finder 風デスクトップで整理・共有するリンク管理アプリです。
閲覧画面（`index.html`）と管理画面（`admin.html`）、メモ帳（`memos.html`）から構成され、
データは Google スプレッドシートに保存します。

> **Note:** このリポジトリはフロントエンド（GitHub Pages）と Google Apps Script（`Code.gs`）の
> 2つのデプロイ先を持ちます。コードだけ更新しても反映されない場所があるので、
> 「セットアップ」と「更新時の注意」を確認してください。

## できること

### 閲覧画面（`index.html`）
- Finder 風のデスクトップ UI（サイドバー、フォルダ、検索）
- カテゴリによるネストフォルダ（カテゴリ名を `/` で区切る）
- お気に入り／最近追加した項目／すべてのリンクの切り替え表示
- リンクの検索、OGP プレビュー付きカード表示、NEW ラベル
- 訪問者ログイン（サイトのパスワード認証、トークン有効期限 6 時間）
- 管理者との共通チャット、お知らせの既読確認
- **テーマ切替（ライト／ダーク）**：ツールバーの ◐ ボタンまたはサイドバーの切替ボタンで
  切り替えられます。既定はダーク（サイバーパンク風）です。選択はブラウザに保存され、
  未選択の場合はダークになります（OS のカラースキーム設定には従いません）。
- **PWA**：ホーム画面への追加に対応。オフラインでも直近に開いた画面を表示できます。
  詳細は「PWA について」を参照してください。
- **ページの共有（QRコード）**：ツールバーの ⤴ ボタンまたはサイドバーの「このページを共有」から、
  このページの QRコードを表示できます。スマートフォンのカメラで読み取ると同じページが開きます。
  URLをコピーするボタンもあります。QRコードはページ内で作るため、外部サービスへ URL を送りません。
  管理画面にも同じボタンがありますが、そこから開く QRコードは閲覧ページ（`index.html`）のものです。

### 管理画面（`admin.html`）
- 管理者ログイン（管理者パスワード認証）
- リンクの追加・編集・削除、フォルダ移動、お気に入り切り替え
- 公式リンク（よく使う公式サイトのクイックランチャー）の管理
- メモ帳（`memos.html` を管理画面内に埋め込み表示）
- 利用者チャットへの返信、クリック履歴（直近 500 件）の確認
- お知らせの既読数の確認、夜間モード（◐ ボタン）
- **ゴミ箱と「元に戻す」**：リンクを削除すると Trash シートへ移動します。
  削除直後に右下へ表示される「削除しました」＋「元に戻す」ボタン（10 秒間）から復元できるほか、
  サイドバーの「ゴミ箱」から一覧を確認して復元・完全削除・ゴミ箱を空にできます。
  公式リンクの削除はゴミ箱の対象外で、従来どおり即削除です。
- **リンク診断**：重複した URL と、開けなくなったリンクを調べます。
  サイドバーの「リンク診断」から「診断する」を押すと、OK／切れている／要確認／重複の
  件数と一覧が表示されます。リンクを保存するとき、同じ URL が既にある場合は
  確認ダイアログが出ます（ブロックはしません）。
- **閲覧ページの共有（QRコード）**：ツールバーの ⤴ ボタンまたはサイドバーの「このページを共有」から、
  閲覧ページの QRコードを表示できます。QRコードは管理者画面ではなく閲覧ページ（`index.html`）の
  URL のものです。

### メモ帳（`memos.html`）
- 管理者専用のメモ帳。管理画面内から開くほか、単体ページとしても開けます。

## リポジトリ構成

| ファイル | 役割 |
|---|---|
| `index.html` | 閲覧画面（訪問者向け）。Finder 風 UI、検索、チャット、お知らせ表示 |
| `admin.html` | 管理画面（管理者向け）。リンク編集、公式リンク、メモ帳、チャット、クリック履歴、ゴミ箱 |
| `memos.html` | メモ帳ページ（管理画面に iframe で埋め込み表示） |
| `bridge.html` | GAS 側の通信窓口（`?mode=bridge` で返す HTML）。ページと GAS を `postMessage` で中継する |
| `Code.gs` | Google Apps Script バックエンド。スプレッドシートの読み書き、認証、キャッシュ |
| `manifest.webmanifest` | PWA マニフェスト（アプリ名、表示方法、アイコン） |
| `sw.js` | Service Worker（オフライン表示用のキャッシュ制御） |
| `link-core-icon.svg` | アプリアイコン（SVG） |
| `apple-touch-icon.png` | iOS ホーム画面用アイコン（180×180） |
| `.github/workflows/jekyll-gh-pages.yml` | GitHub Pages デプロイ用ワークフロー（`main` への push でデプロイ） |

## アーキテクチャ

```
GitHub Pages（静的 HTML: index / admin / memos）
        │  iframe + postMessage（bridge.html 経由）
        ▼
Google Apps Script（Code.gs のウェブアプリ）
        │  SpreadsheetApp
        ▼
Google スプレッドシート（スクリプト プロパティ DAILY_CORE_SPREADSHEET_ID で指定）
```

- フロントエンドはビルド工程のない静的 HTML（CSS・JS は各ファイル内に直書き）です。
- ページは GAS と直接通信せず、`bridge.html` を読み込んだ隠し iframe を中継します。
  `index.html` / `admin.html` 内の `GAS_URL` が、デプロイ済み GAS ウェブアプリの URL です。
- `Code.gs` は `CacheService` でリンク一覧を最大 300 秒キャッシュします。
  更新時はキャッシュを破棄するので、通常は最新の一覧が表示されます。
- 認証はパスワード方式です。トークンはサーバー側のキャッシュに保存され、有効期限は 6 時間です。
  ログイン失敗が続くとレート制限がかかります。

### スプレッドシートのシート一覧

`Code.gs` が必要に応じて自動作成します。手作業で作る必要はありません。

| シート名 | 内容 |
|---|---|
| `Links` | リンク本体（ID、タイトル、URL、カテゴリ、メモ、お気に入り、作成日時、更新日時、利用者に公開、開き方、NEWラベル） |
| `OfficialLinks` | 公式リンク（ID、サイト名、URL、説明、アイコン、種別、作成日時、更新日時） |
| `Memos` | メモ（ID、タイトル、本文、作成日時、更新日時） |
| `ChatMessages` | チャット履歴 |
| `ClickLogs` | クリック履歴（閲覧画面でのリンククリック記録） |
| `NoticeReads` | お知らせの既読記録 |
| `Trash` | ゴミ箱（削除したリンクの退避先。`削除日時` 列付き） |

## セットアップ

### 1. Google Apps Script を用意する
1. Google Apps Script で新しいプロジェクトを作ります。
2. `Code.gs` と `bridge.html` をプロジェクトへコピーします。
   `Code.gs` の `doGet()` は `?mode=bridge` のときに `bridge.html` を返し、
   ページと GAS の通信を中継します。画面自体は GitHub Pages から配信されるため、
   通常の利用では GAS 側の画面表示（`index` ファイル）は使いません。
3. スクリプト プロパティに以下を登録します。

| プロパティ名 | 内容 |
|---|---|
| `DAILY_CORE_SPREADSHEET_ID` | データ保存用の Google スプレッドシートの ID |
| `LINK_CORE_ADMIN_PASSWORD` | 管理者パスワード |
| `LINK_CORE_VISITOR_PASSWORD` | 訪問者（閲覧）用パスワード |

4. ウェブアプリとしてデプロイします。デプロイ後に発行される URL を、
   `index.html` と `admin.html` 内の `GAS_URL` に設定します。
   （2つのファイルは同じ URL を使います）
5. 初回は管理画面を開き、管理者ログインすると必要なシートが自動作成されます。

### 2. GitHub Pages で公開する
1. このリポジトリを `main` ブランチへ push します。
2. `.github/workflows/jekyll-gh-pages.yml` により GitHub Pages へデプロイされます。
3. 公開された URL を開き、訪問者パスワードでログインできることを確認します。

> **`.nojekyll` について**：このリポジトリには `.nojekyll` を置いていません。
> `manifest.webmanifest` と `sw.js` は `_` で始まらない通常ファイルのため、
> Jekyll のビルド対象としてそのまま配信されます。Jekyll の処理を丸ごと無効化する必要はありません。

## 使い方

### 閲覧する（訪問者）
1. 公開 URL を開きます。
2. サイトのパスワード（`LINK_CORE_VISITOR_PASSWORD`）を入力してログインします。
3. サイドバーからフォルダ／お気に入り／最近追加した項目を切り替え、検索欄で絞り込めます。
4. ツールバーの ◐ ボタンでライト／ダークを切り替えられます。

### ページを共有する（QRコード）
- ツールバーの ⤴ ボタン、またはサイドバーの「このページを共有」を押すと、このページの
  QRコードが表示されます。スマートフォンのカメラで読み取ると、同じページが開きます。
- QRコードの下にページの URL も表示されます。「URLをコピー」ボタンで URL をコピーできます。
  クリップボードが使えないブラウザでは、表示された URL を手動でコピーしてください。
- QRコードはページ内で生成するため、外部の QRコード作成サービスへ URL を送ることはありません。
  ダーク／ライトどちらのテーマでも、白い背景に黒い QRコードで表示されるため読み取れます。
- 共有する URL は開いているページのアドレスです（`#` 以降は除きます）。訪問者は共有された
  ページを開いたあと、サイトのパスワードでログインする必要があります。
- 管理画面（`admin.html`）にも同じ共有ボタンがあります。管理者画面の URL をそのまま共有すると
  友達に管理者パスワードを求めてしまうため、管理画面から開く QRコードは閲覧ページ
  （`index.html`）の URL になっています。

### 管理する（管理者）
1. 公開 URL のフッターにある「管理者画面」リンク、または `admin.html` を開きます。
2. 管理者パスワード（`LINK_CORE_ADMIN_PASSWORD`）を入力してログインします。
3. 「リンクを追加」からリンクを登録します。カテゴリに `仕事/資料` のように `/` を入れると
   ネストフォルダになります。
4. カードの「編集」「削除」でリンクを管理します。削除したリンクはゴミ箱へ移動します。

### ゴミ箱を使う（管理者）
- 削除直後：右下のトーストの「元に戻す」を押すと、削除したリンクが一覧に戻ります（10 秒間表示）。
- あとから：サイドバーの「ゴミ箱」を開くと、削除したリンクの一覧が新しい順に表示されます。
  1件ずつ「復元」「完全に削除」ができ、「ゴミ箱を空にする」で全件を完全削除できます。
- 復元すると、タイトル・URL・カテゴリ・メモ・お気に入り・作成日時などは元のまま戻ります。
  ただし同じ ID のリンクが既に一覧にある場合は、重複を避けるため復元せずエラーになります。
- 「完全に削除」「ゴミ箱を空にする」は取り消せません。確認ダイアログが表示されます。

### リンク診断を使う（管理者）
- サイドバーの「リンク診断」を開き、「診断する」を押します。
  8 件ずつ URL を確認するため、件数が多いと数十秒かかることがあります。
  進捗は「診断中… 12/37件のURLを確認中」のように表示されます。
- 診断結果の見方：
  - **OK**：正常に開けました（2xx、またはリダイレクト後の 3xx）。
  - **切れている**：4xx / 5xx が返されました。リンク先が削除・移動している可能性があります。
  - **要確認**：タイムアウト、取得失敗、403（アクセス拒否）など、切れていると断定できなかったものです。
    ボット対策で弾かれただけのこともあるため、ブラウザで直接開いて確かめてください。
  - **重複**：ホスト名の大文字小文字・`www.` の有無・末尾の `/`・`utm_*` などの追跡パラメーターを
    除いて比べ、実質同じ URL のリンクが複数ある場合に表示されます。どちらを残すかは
    タイトル・カテゴリ・作成日時を見て判断してください。
- 一覧の「開く」でリンク先を確認し、「削除」でゴミ箱へ移動できます（復元も可能です）。
  診断自体はリンクを変更・削除しません。
- 診断は GAS からインターネットへアクセスするため、GAS のネットワークが使えることが前提です。
  `Code.gs` や `bridge.html` を変更したときは、GAS の再デプロイが必要です。
  新しいサーバー関数を追加したときは `bridge.html` の `ALLOWED_METHODS` への追加も忘れないでください。

## PWA について

- `manifest.webmanifest` を `index.html` / `admin.html` で読み込み、
  Service Worker（`sw.js`）を登録しています。
- 静的ファイル（HTML、アイコン、manifest）はキャッシュ優先で読み込むため、
  オフラインでも直近に開いた画面が表示されます。
- GAS への通信（リンク一覧・メモ・チャットなど）はネットワーク優先です。
  オフライン時はキャッシュがあればそれを返し、なければエラーになります。
- キャッシュ名にはバージョン（現在は `link-core-v1`）が付いています。
  `sw.js` を更新するときはバージョンを上げてください。古いキャッシュは自動で削除されます。

### アイコンについての注意
- 現在のアイコンは `link-core-icon.svg`（ベクター）と `apple-touch-icon.png`（180×180）のみです。
- ブラウザの「インストール」プロンプトを正式に出すには、192×192 と 512×512 の PNG が必要です。
  ロゴから 192×192 / 512×512 の PNG を書き出し、リポジトリ直下に置いて
  `manifest.webmanifest` の `icons` に追加してください。
  それまではホーム画面への追加（ショートカット）とオフライン表示は利用できますが、
  正式なインストールプロンプトは表示されない場合があります。

## 更新時の注意

- **`Code.gs` や `bridge.html` を変更したら GAS の再デプロイ（新しいデプロイ）が必要です。**
  GitHub へ push しただけでは GAS 側は更新されません。新しいサーバー関数を追加したときは、その関数名を `bridge.html` の `ALLOWED_METHODS` にも追加してください。追加し忘れると「不正なリクエストです」と表示されます。
- **HTML / `manifest.webmanifest` / `sw.js` を変更したら `main` へ push してください。**
  GitHub Pages のワークフローが再デプロイします。
- **`sw.js` を変更したらキャッシュのバージョン（`CACHE_VERSION`）を上げてください。**
  上げないと、古い Service Worker が残り続けることがあります。
- Service Worker は HTTPS（GitHub Pages は HTTPS）でのみ動作します。
  `file://` で直接開いた場合は登録に失敗しますが、閲覧自体は通常どおり動きます。

## トラブルシューティング

| 症状 | 確認すること |
|---|---|
| リンク一覧が更新されない | GAS のキャッシュ（最大 300 秒）の可能性があります。少し待ってから「リンクを更新」を押してください |
| ログインできない | スクリプト プロパティのパスワード設定と、GAS のデプロイ URL（`GAS_URL`）が一致しているか確認してください |
| 「不正なリクエストです」と表示される（`method=getTrash` など） | 新しいサーバー関数が `bridge.html` の `ALLOWED_METHODS` に入っていません。`Code.gs` と `bridge.html` の両方を GAS プロジェクトへコピーし、再デプロイしてください |
| 診断が途中で止まる | 対象サイトの応答が遅い可能性があります。8 件ずつ処理しているため、「診断する」を押すと最初からやり直します。ここまでの結果は残ります |
| 「GASブリッジの準備が10秒以内に完了しませんでした」と表示される | GAS ウェブアプリのデプロイと公開設定を確認してください |
| ゴミ箱が空のはずなのに項目が残る | 復元時に「同じIDのリンクが既にあります」と表示された場合は、一覧に同名リンクがないか確認してください |
| オフラインで画面が開かない | 初回はオンラインで開いてキャッシュを作る必要があります。Service Worker の登録失敗はブラウザの開発者ツールで確認できます |
